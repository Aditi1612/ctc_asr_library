ctc_asr

애플리케이션 내에서 바로 동작하는 한국어 음성 인식 라이브러리 (fine-tuned Wav2Vec2-CTC), 준실시간 스트리밍 지원.

GitHub: github.com/Aditi1612/ctc_asr_library  ·  모델: huggingface.co/fluffy16/ctc-asr-ko  ·  v0.1.0

개요

한국어 ASR 모델을 애플리케이션 프로세스 안에서 직접 실행하는 Python 라이브러리입니다. HTTP 서버도, API 엔드포인트 호출도 필요 없습니다. 모델을 한 번만 로드한 뒤 함수를 호출하면 됩니다.

  • 단건(one-shot): 오디오 파일이나 파형을 넘기면 전사 결과를 돌려줍니다.
  • 스트리밍: 마이크 프레임을 계속 밀어 넣으면, 화자가 말을 멈출 때마다 해당 발화의 전사 결과를 반환합니다 (음성 구간 검출 기반 분할).

디코딩 경로(오디오 정규화, 자모 정규화, 한글 조합, CTC 디코딩)는 운영 중인 API와 동일하므로 출력 결과도 같습니다.

요구 사항

구성 요소설명
Python3.9 이상
torch, torchaudio 사용하는 환경(CUDA 또는 CPU)에 맞는 빌드를 먼저 설치하세요. 용량이 크고 하드웨어에 종속적입니다.
GPU선택 사항. CUDA에서는 클립당 약 25 ms, CPU에서도 충분히 빠릅니다(오디오 1초당 약 0.04 s).
디스크모델 약 1.3 GB. 최초 1회 다운로드 후 ~/.cache/huggingface에 캐시됩니다.

빠른 시작 — 단건 전사

from ctc_asr import Transcriber

asr = Transcriber(hf_repo="fluffy16/ctc-asr-ko")   # 최초 실행 시 약 1.2 GB 다운로드, 이후 캐시

print(asr.transcribe("clip.wav"))                  # -> "카촉틀과 토이띠차 내뒤에 안자쩌요"

# 파일 대신 원본 파형(mono float32)을 직접 전달:
import soundfile as sf
wav, sr = sf.read("clip.wav", dtype="float32")
print(asr.transcribe(wav, input_sr=sr))

# 상세 결과 (원본 텍스트, reference_text 전달 시 CER, 처리 시간):
asr.transcribe("clip.wav", detailed=True)

입력으로 파일 경로, 인코딩된 바이트(wav/flac/ogg, ffmpeg가 있으면 mp3/m4a도 가능), 또는 numpy / torch 파형을 받습니다.

스트리밍 (준실시간)

애플리케이션이 어디서든 오디오를 캡처해 길이에 상관없이 mono float32 청크로 밀어 넣습니다. 화자가 말을 멈추면 그때까지 버퍼링된 발화가 전사되어 반환됩니다. 부분 가설(partial)은 없으며, 발화 단위로 완성된 전사만 제공됩니다. 

from ctc_asr import Transcriber

asr = Transcriber(hf_repo="fluffy16/ctc-asr-ko")
stream = asr.stream(on_segment=lambda s: print(f"[{s.start_time:.1f}s] {s.text}"))

for chunk in your_mic_source():                 # 예: 20~100 ms 블록, 샘플레이트 무관
    for seg in stream.accept(chunk, input_sr=48000):   # 필요 시 내부에서 리샘플링
        handle(seg.text, seg.start_time, seg.end_time)

last = stream.flush()                            # 스트림 종료 시 남은 발화를 마무리 처리

accept()는 이번 호출에서 확정된 Segment 목록을 반환합니다. 보통은 비어 있고, 발화가 막 끝났을 때 하나가 담깁니다. 마이크 입력을 기다리며 블로킹하지 않으며, 멈춤(pause)이 감지될 때만 모델이 실행됩니다.

asr.stream(...) 튜닝

인자기본값의미
end_silence_ms600발화를 끝내는 침묵 길이 — 체감 지연 시간과 거의 같음
min_speech_ms250이보다 짧은 발화는 잡음으로 간주해 버림
max_speech_ms15000멈춤 없이 이어지는 구간을 강제로 끊는 한계
start_speech_frames3캡처를 시작하는 데 필요한 연속 음성 프레임 수
pre_roll_ms200트리거 직전 오디오를 함께 보관해 발화 시작이 잘리지 않게 함
vad_aggressiveness2webrtcvad 민감도 0~3 (높을수록 비음성 판정이 공격적)

모델을 가져오는 위치

해석 우선순위: 명시적 경로 → Hugging Face 저장소 → 로컬 sibling 체크아웃.

소스방법
Hugging Face HubTranscriber(hf_repo="fluffy16/ctc-asr-ko")  또는  export CTC_HF_REPO=fluffy16/ctc-asr-ko
로컬 파일Transcriber(model_dir="/path/checkpoint", vocab_path="/path/vocab.json")  또는  CTC_MODEL_DIR / CTC_VOCAB_PATH
버전 고정Transcriber(hf_repo="fluffy16/ctc-asr-ko", hf_revision="<commit-sha>")
현재 Hugging Face 모델 저장소는 공개(public) 상태라 토큰이 필요 없습니다. 이후 비공개로 전환되면, 각 사용자는 huggingface-cli login을 1회 실행하거나 HF_TOKEN을 설정하고, 저장소 협업자로 추가되어야 합니다.

성능 (샘플 세트 측정값)

모델이 이미 로드된 상태에서 transcribe() 호출만 측정한 시간입니다.

오디오 길이GPU (CUDA)CPU
2 초0.012 초0.11 초
5 초0.025 초0.20 초
14 초0.026 초0.62 초
22 초0.034 초0.83 초
  • GPU: 클립 길이와 무관하게 약 25 ms (실시간 배속 계수 RTF ≈ 0.003).
  • CPU: 오디오 1초당 약 0.04초, 길이에 선형 비례 (RTF ≈ 0.04).
  • 메모리로 모델 로드: Transcriber(...) 시점에 1회, 약 0.4초.
  • Hugging Face 최초 다운로드: 약 1.2 GB — 네트워크에 따라 다르며 이후 영구 캐시.

제약 사항

  • 모델은 발화 전체를 전사합니다. 단어 단위 실시간 출력은 없으며, “실시간”은 멈춤 직후 전사가 나타난다는 의미입니다.
  • 침묵을 기준으로 분할하므로 경계에서 단어가 잘릴 수 있습니다. 멈춤 없이 길게 말한 문장은 같은 오디오를 하나의 클립으로 보낼 때와 결과가 약간 다를 수 있습니다.
  • 하나의 Transcriber는 한 번에 하나의 추론만 수행합니다. 병렬 처리가 필요하면 워커 스레드 / 프로세스마다 인스턴스를 하나씩 두세요.
  • 출력은 한국어 전용이며, 모델은 마비말·비정형 발화에 맞게 파인튜닝되어 있습니다.
